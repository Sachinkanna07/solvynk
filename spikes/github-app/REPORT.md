## D-037 finding and next gate

GitHub documentation says automatic OAuth during installation redirects to the App callback and makes Setup URL unavailable. It does not establish that the installation URL's `state` reaches that callback alongside `installation_id`, or that the automatic authorization can use a challenge generated by this receiver. The receiver therefore treats the automatic return only as an installation-intent handoff: it requires the original install state, ignores any automatic code, and initiates a new explicit PKCE flow before using a fresh user token to verify ownership. If the actual callback lacks the state or installation ID, the receiver rejects it. Disabling automatic authorization and using a separately verified Setup URL is the proposed alternative, but D-037 needs a founder decision before that settings change.

The remaining prerequisite to an installation result is for the founder to visit `/github/connect` in the same local browser session, install the App on one selected public personal repository, and inspect the automatic installation return. A read-only App JWT `GET /app/installations` check after the successful sign-in returned HTTP 200 with zero installations. Keep webhooks inactive until a separate approved HTTPS receiver and secret are ready. No production readiness or T-004 acceptance is claimed.
